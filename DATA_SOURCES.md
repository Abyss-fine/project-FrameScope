# Источники данных FrameScope — Backend v0.1

Проверено **31 октября 2026 года**. В рабочую SQLite импортированы два открытых источника. Браузер обращается только к нашему Express API; внешние данные загружаются административной командой `npm run import`. Секретные ключи не нужны.

## PC Game FPS Dataset / PCGameBenchmarks

Источники: [репозиторий](https://github.com/emilioagustin83/pc-game-fps-dataset), [описание](https://github.com/emilioagustin83/pc-game-fps-dataset/blob/main/README.md), [games.csv](https://github.com/emilioagustin83/pc-game-fps-dataset/blob/main/data/games.csv), [gpus.csv](https://github.com/emilioagustin83/pc-game-fps-dataset/blob/main/data/gpus.csv), [лицензия CC BY 4.0](https://github.com/emilioagustin83/pc-game-fps-dataset/blob/main/LICENSE).

CSV содержит 17 427 игр и 1381 GPU в справочнике. Колонки `fps_1080p_high_*` — **модельные оценки** для 12 эталонных GPU, не измерения пользовательского ПК. Импортируются только существующие значения для 1920×1080 / High; источник указывает отсутствие RT, апскейлинга и генерации кадров. Поля `min_cpu`/`min_ram_gb` — системные требования, их нельзя считать конфигурацией замера.

Атрибуция — **PCGameBenchmarks**, ссылка [pcgamebenchmarks.com](https://pcgamebenchmarks.com). Указываем CC BY 4.0 и изменения: названия нормализованы, данные переведены в реляционную структуру. Оценки не пересчитываются по рейтингу GPU.

## Open GPU Benchmarks

Источники: [сайт](https://opengpubenchmarks.com/), [JSON API](https://opengpubenchmarks.com/api/v1/dashboard.json), [условия и CC BY 4.0](https://opengpubenchmarks.com/license/).

Проверен JSON со схемой **0.20**, release **1.13.0.0**, commit **fc94e56089f3**, generated_at **2026-10-27T16:54:38.141259+00:00**. Данные имеют лицензию CC BY 4.0, код сайта — отдельную MIT-лицензию; тексты обзоров не входят в разрешение на данные.

Из 31 записи импортированы **27 одиночных игровых измерений** Cyberpunk 2077 / GeForce RTX 5080 Founders Edition. Три сводки нескольких запусков пропущены: группировка источника не гарантирует одинаковые версии и все условия. Одна запись синтетического OpenBenchmarker Neon Flythrough пропущена по `game_type`, даже несмотря на `synthetic:false` у этой записи.

Сохраняются FPS, 1% Low, CPU, RAM, версия игры, дата, драйвер, ОС, известные режимы, число запусков, исходный ID/путь и сведения о тесте. Нагрузка CPU/GPU не выводится из FPS. Общий временной ряд API не предоставляет. Обычный пресет High не доказывает off для RT: неизвестное остаётся NULL. Пустой upscaling также не превращается в off. `frame_generation:false` явно соответствует off.

Атрибуция — **Open GPU Benchmarks** со ссылкой на API и [сайт](https://opengpubenchmarks.com). Изменения: нормализация строк и импорт проверенных одиночных записей в SQLite. Авторство записей и credits сохраняются в `conditions_json`; не заявляется поддержка FrameScope авторами источника.

## Версии, повторяемость и кэш

Обычный импорт сначала получает commit PC Dataset из GitHub API, затем скачивает оба CSV и лицензию по закреплённому commit. Рабочая версия записей — SHA-256 содержимого обоих CSV. Для Open GPU используется commit из JSON вместе с SHA-256 снимка. Благодаря этому одинаковый онлайн- и офлайн-импорт имеет одинаковую идентичность.

Уникальность `benchmark_sources(name,dataset_version)` + `benchmarks(source_id,external_key)` предотвращает повторный импорт тех же записей. Новый снимок создаёт отдельную версию; старый не удаляется. Отчёт `data/import-report.json` показывает вставленные записи, дубли и причины пропуска. Обработка каждого источника транзакционная; при его недоступности второй всё равно проверяется. Старый кэш молча не подставляется: для него есть явный `--offline`.

Загрузки ограничены по времени и объёму (45 секунд, 64 MiB на файл). Кэш, SQLite и отчёт исключены из Git. В кэше сохраняются исходные файлы и лицензия PC Dataset. Публичные страницы содержат атрибуцию обоих источников и ссылку CC BY 4.0.

## Идентичность и нормализация

- Игры связываются по точному Steam ID; при его отсутствии — по URL источника. Одинаковое или похожее название не является достаточным совпадением.
- Явно подтверждён псевдоним Alan Wake II → исходная запись Alan Wake 2 при отсутствии Steam ID. Baldur’s Gate III связывается с Baldur’s Gate 3 по Steam ID 1086940.
- GTA V Legacy (Steam 271590), Enhanced (3240220), дополнения и записи без подтверждённого ID не склеиваются. Неоднозначные строки могут оставаться отдельными играми.
- У GPU нормализуются регистр, пробелы и префикс производителя; сохраняются Ti, SUPER, Laptop, Founders Edition, объём памяти и класс устройства. Мобильная и настольная версии различаются. Эталонные GPU привязаны по точному имени и типу из CSV.
- Суффикс CPU вида «16-Core Processor» убирается только из ключа идентичности; исходное название сохраняется.
- Отсутствующие значения — NULL. Недостоверные оценки влияния CPU, RAM или другой версии игры не добавляются.

## Справочник графических настроек интерфейса

Отдельный справочник в src/data/graphics-profiles.js описывает проверенное подмножество возможностей Cyberpunk 2077 и Control Ultimate Edition. Он не изменяет импортированные бенчмарки и не определяет установленную у пользователя версию игры. Технология может поддерживаться игрой, но не иметь записи FPS в нашей базе. У остальных игр неподтверждённые технологии не предлагаются.

Проверенные первичные источники:

- [CD Projekt RED: обновление 2.3](https://www.cyberpunk.net/fr/news/51683/notes-de-patch-2-3) — поддержка FSR 3.1 FG и XeSS 2.0. Новые драйверные возможности не приписываются всем GPU. Для FSR 2.1 дополнительно подтверждены явные значения в импортированном JSON.
- [NVIDIA DLSS](https://www.nvidia.com/en-us/geforce/technologies/dlss/) — различие Super Resolution, Frame Generation и Multi Frame Generation. В форме MFG не реализована.
- [AMD GPUOpen, FSR 3.1](https://gpuopen.com/learn/amd_fsr_3_1_release/) — совместимость FSR 3.1 с Radeon RX 5000+ и GeForce RTX 20+. Профиль использует консервативное подмножество сочетаний.
- [Intel XeSS 2](https://www.intel.com/content/www/us/en/developer/articles/technical/xess2-whitepaper.html) — XeSS и генерация кадров, подтверждённая для Arc с XMX. Кросс-вендорные варианты более новых SDK не считаются автоматически доступными в выбранной игре.
- [NVIDIA: DLSS 2.0 и Control](https://www.nvidia.com/en-gb/geforce/news/nvidia-dlss-2-0-a-big-leap-in-ai-rendering/) — Quality/Balanced/Performance в Control соответствуют выбору Rendering Resolution.
- [Remedy: Control Ultimate Edition 1.30](https://remedy.helpshift.com/hc/en/4-control-ultimate-edition/faq/164-control-ultimate-edition---v1-30-pc-update-notes-1772026035/) — RT Ultra и обновление DLSS. Это метаданные справочника, а не предположение о версии пользователя.

Записи источника с NULL RT/апскейлингом/FG сохраняются. В пользовательской форме NULL не является выбираемой настройкой; такие условия не переносятся автоматически. Технический старый формат API с явным unknown поддержан отдельно с предупреждениями.

## Производные прогнозы FrameScope

Импортированные значения не перезаписываются. Сначала ищется точная запись игры/GPU/настроек; измерения дополнительно требуют совпадения CPU/RAM/ОС и имеют приоритет. Совпавшая модельная оценка остаётся `estimated`, не становится измерением.

Если точной записи нет, сервер может взять ближайшую основу той же игры и точного GPU, с совпадающими полностью известными RT/апскейлингом/FG. Пересчитываются только разрешение и обычный пресет: исходный FPS умножается на отношения весов целевого и исходного условий. Веса разрешений: 1080p — 1, 1440p — 0.72, 2160p — 0.40; пресетов: low — 1.35, medium — 1.15, high — 1, ultra — 0.85.

**Это допущения FrameScope, не коэффициенты источников и не проверенная точность.** Ответ имеет `resultType=estimated`, `method=heuristic`, `confidence=low`, исходную запись и коэффициенты. Оценки округляются; атрибуция и CC BY 4.0 сохраняются. Производный результат не записывается в таблицу измерений. CPU/RAM не масштабируют исходную модель. Нет коэффициентов RT, DLSS/FSR/XeSS или FG и переноса между GPU/играми.

Явный положительный `engine_fps_cap` из CSV сохраняется в `games.fps_cap` и ограничивает прогноз, если исходный FPS не противоречит пределу. Для производных оценок PCGameBenchmarks конфигурация ограничивает FPS значением 360. Неизвестные лимиты не угадываются. 1% Low, загрузка и временной ряд не выводятся из среднего FPS.

Форма использует `settings.analysis`: пересечение проверенного профиля игры/GPU и полностью описанных записей. Если кроме off ничего нет, блок дополнительных настроек скрыт. Старый технический API сохраняет точный просмотр записей с явно неизвестными режимами; эвристика их не пересчитывает.

[Формула, уверенность и ограничения](docs/FORECAST.md). Уверенность — качественная категория, не процент вероятности. Без подходящей основы возвращается недостаточность данных.

## Архив исследования frontend и изображения

[Полная предварительная документация frontend](docs/DATA_SOURCES_FRONTEND.md) сохранена. RAWG не подключён; условия его использования и изображения требуют отдельной проверки. CapFrameX / PresentMon остаются кандидатами для собственных замеров, а не текущими источниками базы. Неустановленные права на результаты OpenBenchmarking.org не используются.

Исходные авторские описания десяти игр, ссылки на их страницы и две проверенные даты сохранены. У прочих игр отсутствующие описания/жанры/даты не выдумываются. Все SVG оригинальные, не являются официальными обложками. Bootstrap хранится локально с MIT-лицензией в `public/assets/vendor/bootstrap/LICENSE`.
