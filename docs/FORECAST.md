# Прогноз FPS и упрощённый интерфейс

Текущая модель — `heuristic-v1`. Это учебная эвристика: понятная формула с допущениями, без обучения и проверки точности на независимых замерах. Коэффициенты не получены от производителей и не являются универсальными законами производительности.

**Выбранная система расчётов не является финальной и нуждается в дальнейшей доработке.** По мере развития проекта необходимо проверить точность прогнозов на независимых измерениях, откалибровать коэффициенты и уточнить учёт характеристик ПК и игровых настроек. Формула, коэффициенты и правила выбора исходных данных могут изменяться по результатам этих проверок.

## Как выбирается результат

1. Сервер проверяет ID игры и оборудования, RAM и графические режимы.
2. Ищет ту же игру, точный GPU, разрешение, пресет и режимы RT/апскейлинга/FG. Для измерения дополнительно нужны совпадение CPU, RAM и ОС. Если задана версия игры, она также должна совпасть.
3. Из точных совпадений приоритет имеет измерение; затем используются дата замера, дата импорта и ID. Одна запись не усредняется с несовместимыми запусками.
4. Если точного результата нет, ищется основа для **той же игры и того же GPU**. Все три дополнительных режима должны быть известны и совпадать с запросом. Требования к CPU/RAM/ОС измерения сохраняются.
5. Из подходящих основ выбирается ближайшая по разрешению и обычному пресету. Расстояние — сумма абсолютных логарифмов двух коэффициентов. При равенстве сохраняется приоритет измерения и свежести.
6. Если основы нет, возвращается `INSUFFICIENT_DATA` без FPS. Ручные названия оборудования не сопоставляются с похожими моделями и возвращают `MANUAL_HARDWARE_NO_DATA`.

## Формула

Настройки находятся в `src/config/forecast.js`; вычисления — в `src/services/forecast.js`.

```text
FPS = исходный FPS
    × вес целевого разрешения / вес исходного разрешения
    × вес целевого пресета / вес исходного пресета
```

| Разрешение | Вес |
| --- | --- |
| 1920×1080 | 1 |
| 2560×1440 | 0.72 |
| 3840×2160 | 0.40 |

| Обычный пресет | Вес |
| --- | --- |
| Low | 1.35 |
| Medium | 1.15 |
| High | 1 |
| Ultra | 0.85 |

Например, импортированная **оценка** Control / RTX 4070 составляет 172 FPS в 1080p High. Для 1440p High: `172 × 0.72 = 123.84`, на экране **≈125 FPS**. Это новый прогноз FrameScope на основе оценки источника, не измерение. Точное значение этой модельной записи тоже отображается округлённо: **≈170 FPS**.

Оценки от 20 FPS округляются до ближайших 5, ниже — до целого, минимум 1. Реальные измерения не округляются моделью. Для производных оценок PCGameBenchmarks применяется потолок 360 FPS из конфигурации. Явный `engine_fps_cap` из CSV сохраняется в `games.fps_cap` и ограничивает прогноз, если исходное значение не противоречит этому пределу. Это не определение пользовательского ограничителя FPS. При активном ограничении причина указана в объяснении. Неподдерживаемые разрешения/пресеты не пересчитываются.

## Тип результата и уверенность

| Метод | resultType | confidence |
| --- | --- | --- |
| Совпавший реальный замер | measured | high; medium при явно неизвестных режимах технического API |
| Совпавшая модельная оценка датасета | estimated | medium |
| Пересчёт разрешения/пресета FrameScope | estimated | low |

Уверенность — условная характеристика основы расчёта, не вероятность и не статистический интервал. Даже `high` не гарантирует FPS на другом ПК. Модельная оценка никогда не становится измерением из-за совпадения настроек.

Ответ API содержит `method`, `explanation`, `sourceName`, `sourceUrl`, исходную запись в `basis`, коэффициенты и пределы в `adjustments`. Производные результаты вычисляются при запросе и не записываются в таблицу измерений. Ссылка и лицензия исходных данных сохраняются.

## Что учитывается и что ограничено

- Учитываются точные игра/GPU, исходный FPS, разрешение и обычный пресет; режимы используются как строгий фильтр. Версия игры — необязательный фильтр API.
- CPU/RAM не изменяют оценку PCGameBenchmarks. Для измерения они только проверяются на совпадение; отдельной модели их влияния нет.
- Нет коэффициентов для RT, DLSS, FSR, XeSS или FG. Нельзя взять запись с выключенным режимом и придумать прибавку или потерю FPS для включённого.
- NULL режима не равен off. Пересчёт записей с неизвестными режимами запрещён; их точный просмотр возможен через старый технический API.
- При пересчёте 1% Low и загрузка CPU/GPU остаются NULL даже при наличии этих показателей в исходном замере. Нет временного графика из одного среднего FPS.
- Не моделируются сцена, драйвер, частоты, охлаждение, VRAM, тип/каналы RAM, ограничения CPU и разница версий игры. Общие коэффициенты могут давать существенную ошибку, особенно при CPU-ограничении. Пересчёт уже модельной оценки наследует её ошибки.
- Справочник содержит больше устройств, чем база FPS. Наличие GPU в поиске не обещает результат. Перенос между похожими GPU и между играми отсутствует.

## Как изменился интерфейс

Игра выбирается в одном поле: ввод → серверные подсказки → выбор → сохранённый ID. Печатать название недостаточно: нужна подсказка. При редактировании ID сразу очищается. Поддержаны клавиши ↑/↓, Enter, Escape, мышь и касание. На странице конкретной игры поле заполнено и доступно только для чтения.

Убраны отдельный поиск перед списком игр, видимые служебные статусы выбора, панель «Данные источников…», версия игры и декоративная область графика. Статусы для скринридера сохранены. Результат содержит показатели, тип, уверенность, короткое основание и источник; подробности свёрнуты.

Дополнительные настройки берутся из `settings.analysis`: пересечение проверенного профиля игры/GPU и записей с полностью известными режимами. Если кроме off ничего нет, блок скрыт; off отправляется явно. Поддержка технологии игрой сама по себе не открывает её в форме. При выбранном недоступном сочетании сервер по-прежнему может отказать: наличие каждого режима отдельно не доказывает наличие всех их комбинаций.

Преимущества главной: анализ производительности; Companion и сообщество отмечены «В разработке». Сравнение сборок также ещё в разработке.
