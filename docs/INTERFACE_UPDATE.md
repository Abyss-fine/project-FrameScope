# Обновление интерфейса: поиск железа и графические настройки

> Историческое описание предыдущего этапа. Текущий единый поиск игры, скрытие недоступных режимов и эвристика описаны в [FORECAST.md](FORECAST.md). Панель источников из формы удалена.

## Поиск CPU / GPU

Вместо select используются собственные комбобоксы. Ввод отправляет GET /api/hardware/cpus либо /gpus с search и limit=25. Запросы откладываются на 180 мс, устаревшие отменяются; старый ответ не открывает подсказки после Escape или изменения текста. Текст поиска передаётся параметрами SQL. Устройства не добавляются в HTML вручную.

ArrowDown/ArrowUp перемещают активную подсказку, Enter выбирает, Escape закрывает список. Поддержаны мышь, касание и кнопка очистки. Есть связанные label, combobox/listbox/option, aria-expanded, aria-activedescendant и статус выбора для скринридера.

Выбор подсказки сохраняет реальный ID в состоянии компонента. Редактирование текста сразу сбрасывает ID. Ручной выбор хранит текст в текущей форме, не записывает его в SQLite и не выбирает похожую модель. После перезагрузки страницы несохранённая конфигурация сбрасывается. Произвольное название — не доказательство совместимости DLSS/FG: расширенные технологии для него не предлагаются.

Варианты SUPER/Ti/Founders Edition и классы Desktop/Mobile показываются отдельно. Поиск может предложить похожие записи, но только пользователь решает, какую выбрать. Даже точное вручную набранное название без выбора подсказки не привязывается автоматически к потенциально неоднозначному устройству.

## Новое API

- GET /api/hardware/cpus и /gpus: search, limit (1–2000), offset. Без параметров прежний список остаётся доступен. Поиск выполняется по всем словам без учёта регистра.
- GET /api/games/:id/settings?gpuId=...: профиль игры, разрешённые RT, технологии/версии и режимы апскейлинга, технологии FG, примечания и источники. ID или slug игры сохранены.
- POST /api/benchmarks/estimate: вместо каждого CPU/GPU ID можно передать cpuName/gpuName. Это возвращает MANUAL_HARDWARE_NO_DATA, не 500, и не создаёт новую запись.
- Новый запрос содержит upscalingTechnology и upscalingQuality; старый явный upscalingMode поддерживается отдельно. Новые значения проверяются сервером, независимо от UI.
- Пропущенные режимы больше не считаются off: SETTINGS_REQUIRED. Это согласованное изменение клиента и API. Старые запросы с явными режимами продолжают работать.

Пример нового формата для исходной базы:

```json
{
  "gameId": 1,
  "cpuId": 1,
  "gpuId": 4,
  "ramGb": 32,
  "resolution": "1920x1080",
  "graphicsPreset": "high",
  "rayTracingMode": "off",
  "upscalingTechnology": "dlss",
  "upscalingQuality": "quality",
  "frameGenerationMode": "off"
}
```

ID надо сверять с API. Поддержка DLSS Quality не создаёт FPS: без точной записи будет INSUFFICIENT_DATA. Для Native отправляется quality=null. Выбор версии FSR в технологии формирует точную строку, например fsr 2.1 quality, без переноса результатов другой версии.

## Справочник настроек

src/data/graphics-profiles.js — отдельные проверенные профили Cyberpunk 2077 и Control. src/services/graphics-settings.js фильтрует профиль по GPU из базы и проверяет новые запросы. Для расширения добавляется профиль, а не переписывается форма.

| Игра | RT | Апскейлинг | FG |
| --- | --- | --- | --- |
| Cyberpunk 2077 | Off, Low, Medium, Ultra, отдельный Overdrive | DLSS, FSR 2.1, XeSS 2.0 — только проверенные GPU и подмножества режимов | DLSS FG, FSR 3.1 FG, XeSS 2.0 FG — с ограничениями совместимости |
| Control Ultimate Edition | Off, Medium, High; Ultra для обновления 1.30 | DLSS; Quality/Balanced/Performance представлены как эквиваленты Rendering Resolution | В справочнике не подтверждена, только off |
| Другие игры | Пока только off | Пока Native | Пока off |

Это консервативный справочник, а не полная матрица всех существующих GPU, патчей, драйверов и интеграций. DLSS SR предлагается подтверждённым GeForce RTX 20/30/40/50. DLSS FG — RTX 40/50. FSR — проверенному подмножеству RTX и Radeon RX 5000+. XeSS пока — Arc A/B; остальные поддерживаемые платформы требуют отдельного подтверждения. RT разрешён только распознанным семействам DXR. Отсутствие технологии в нашем списке не означает, что игра или GPU вообще её не поддерживают.

Для FG дополнительно проверяется сочетание с апскейлером. В текущем консервативном профиле DLSS FG показывается с DLSS, FSR 3.1 FG — с подтверждёнными апскейлерами (включая FSR 2.1 и DLSS), XeSS FG — с XeSS 2.0. Поддержка FSR 3.1 FG сама по себе не доказывает наличие FSR 3.1 Super Resolution: отдельный пункт такого апскейлинга не добавлен. Это подмножество подтверждённых возможностей, а не утверждение об отсутствии других комбинаций. Multi Frame Generation, драйверные overrides, модификации и новые версии вне профиля не предлагаются.

Качество скрывается и исключается из Native-запроса. При смене GPU/игры совместимые значения сохраняются, неподтверждённые сбрасываются с сообщением. Поле версии игры удалено; дата и версия бенчмарка остаются метаданными результата. Профиль описывает документированный набор, не определяет установленную у пользователя версию.

## Неизвестные условия источника

NULL не превратился в off. В интерфейсе нет опции «Неизвестно (как в источнике)». Записи с отсутствующими или непредставимыми условиями можно изучить по ссылке на источник, но нельзя перенести в пользовательскую конфигурацию. Старый технический API с явным unknown оставлен для просмотра записей с предупреждениями; новый пользовательский формат требует реальных настроек.

Сам импорт и его 209151 запись не менялись. Схема SQLite и миграции не менялись. Нет дополнительной таблицы для непроверенного пользовательского железа.

## Проверки

27 встроенных тестов Node.js: поиск SUPER/Ti/Mobile, валидация ручных названий, отсутствие вставок в справочники, несовместимые технологии, точные строки DLSS, неполные настройки, прежние API/импорт/ограничения SQLite.

69 браузерных проверок: четыре клавиши комбобокса, мышь, выбор GPU касанием на эмулированном мобильном экране, видимость раскрытых подсказок, ручной CPU/GPU, Native/DLSS Quality/RT/FG, отсутствие поддержки, отсутствие FPS, отмена старых ответов, сохранение результата при потере фокуса без редактирования, мобильное меню, карусель, каталог, десять страниц игр, адаптивность 320–1920 px, отсутствие ошибок JS. Подсказки раскрываются вверх при нехватке места снизу и учитывают видимую область при экранной клавиатуре. Скриншоты: test-artifacts/interface-1440.png и interface-375.png. Проверка реального физического телефона и других браузеров пока не выполнялась.

Проверка запуска: npm run dev, затем http://localhost:3000. Старый Live Server не обслуживает API. Если браузер показывает прежние модули, обнови страницу Ctrl+F5.
