# FrameScope

Веб-приложение для ориентировочной оценки производительности компьютерных игр по характеристикам ПК и выбранным настройкам графики.

**Учебный проект. Автор — Вагелист Дмитрий, группа ЭФБО-15-25.**

## О проекте

FrameScope помогает найти доступные данные о производительности игры для выбранной видеокарты и получить ориентировочный FPS. Пользователь выбирает процессор, видеокарту, объём оперативной памяти, игру, разрешение и качество графики. Сервис показывает результат, источник данных и пояснение к оценке.

Проект создан для изучения разработки веб-приложений: адаптивного интерфейса, серверного API, реляционной базы данных, импорта открытых данных и автоматического тестирования.

## Возможности

- Поиск игр, процессоров и видеокарт через поля с подсказками.
- Каталог игр с поиском, фильтрацией и постраничной загрузкой.
- Отдельная страница каждой игры с формой оценки производительности.
- Поиск бенчмарков и модельных оценок в SQLite.
- Ориентировочный пересчёт FPS для другого разрешения или пресета при наличии подходящей основы.
- Отображение типа результата, уровня уверенности, источника и ограничений.
- Адаптивный интерфейс с поддержкой клавиатуры и сенсорного ввода.

Автоматическое определение комплектующих пока не реализовано: конфигурация выбирается вручную. Сравнение сборок, приложение FrameScope Companion, профили пользователей и сообщество находятся в планах.

## Как рассчитывается FPS

Сначала сервер ищет запись для той же игры, точной модели GPU и выбранных настроек. Для реального измерения дополнительно требуется совпадение процессора, объёма RAM и операционной системы.

Если точного результата нет, сервис ищет ближайшую подходящую основу для **той же игры и видеокарты** и пересчитывает средний FPS с помощью коэффициентов разрешения и обычного пресета графики. Такой результат отмечается как ориентировочный прогноз с низкой уверенностью. Без подходящей основы сайт сообщает о недостатке данных.

**Прогноз не гарантирует FPS на конкретном компьютере.** Коэффициенты являются учебными допущениями и пока не откалиброваны на независимых измерениях. Модельная оценка источника также не считается реальным бенчмарком.

Основные ограничения:

- Влияние CPU и RAM на модельные оценки отдельно не рассчитывается.
- Нет произвольных коэффициентов для RT, DLSS, FSR, XeSS и генерации кадров.
- FPS не переносится между разными играми или похожими моделями видеокарт.
- 1% Low и загрузка компонентов показываются только при наличии соответствующих данных; неизвестные значения остаются прочерками.
- Наличие видеокарты в справочнике не означает наличие данных FPS для неё.

Подробнее: [формула прогноза и ограничения](docs/FORECAST.md).

## Технологии

| Часть проекта | Технологии |
| --- | --- |
| Интерфейс | HTML, CSS, JavaScript, Bootstrap 5.3.8 |
| Сервер | Node.js 24, Express 5 |
| База данных | SQLite, better-sqlite3 |
| Импорт данных | CSV и JSON, csv-parse |
| Проверки | Встроенный тестовый модуль Node.js, браузерные проверки в Chrome |

Express обслуживает и страницы, и API. Отдельный сервер базы данных и сборка frontend не требуются.

## Локальный запуск

Потребуются **Node.js 24.x** с npm и интернет для первоначального скачивания зависимостей и данных.

Скачайте репозиторий или клонируйте его через Git. Откройте терминал в корневой папке проекта и выполните:

```bash
npm install
npm run db:init
npm run import
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Терминал должен оставаться открытым, пока используется сайт. Для остановки сервера нажмите `Ctrl+C`.

Сайт нужно запускать через Express: открытие `index.html` напрямую или через Live Server не обеспечивает работу API.

В Windows PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`, например `npm.cmd run dev`.

### Команды

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Запуск с автоматическим перезапуском серверного кода |
| `npm start` | Обычный запуск сервера |
| `npm run db:init` | Создание базы, применение миграций и добавление начальных справочников |
| `npm run import` | Загрузка и импорт открытых данных |
| `npm run import:offline` | Импорт из ранее скачанного кэша без интернета |
| `npm test` | Запуск серверных и модульных тестов |
| `npm run test:browser` | Проверка интерфейса в установленном Chrome |

База SQLite и кэш источников не входят в репозиторий. После скачивания проекта импорт необходимо выполнить локально. Повторный импорт одинакового снимка не создаёт дубли. Ошибки источников записываются в `data/import-report.json`; существующая база не очищается.

### Настройка окружения

По умолчанию файл `.env` не требуется. Для изменения настроек скопируйте `.env.example` в `.env`:

```dotenv
HOST=127.0.0.1
PORT=3000
DB_PATH=data/framescope.sqlite
```

`HOST` задаёт адрес сервера, `PORT` — порт, `DB_PATH` — путь к базе относительно корня проекта. Ключи внешних API для текущей версии не нужны.

## Источники данных

- [PC Game FPS Dataset / PCGameBenchmarks](https://github.com/emilioagustin83/pc-game-fps-dataset) — каталог игр и GPU, модельные оценки FPS.
- [Open GPU Benchmarks](https://opengpubenchmarks.com/) — отдельные реальные измерения с условиями тестирования.

Данные этих источников используются с атрибуцией по лицензии **CC BY 4.0**. Производные оценки FrameScope явно отделяются от исходных измерений. Лицензии данных и сторонних библиотек не являются лицензией всего проекта.

Подробности импорта, происхождения данных и лицензий: [DATA_SOURCES.md](DATA_SOURCES.md). Изображения игр в интерфейсе — оригинальные иллюстрации-заглушки, а не официальные обложки.

## Структура репозитория

```text
public/          Страницы, стили, клиентский JavaScript и изображения
src/             Express-приложение, API и логика подбора результатов
  config/        Коэффициенты прогноза
  db/            Подключение SQLite, миграции и начальные данные
  repositories/  SQL-запросы к базе
  services/      Проверка параметров, импорт и прогнозирование
scripts/         Инициализация базы и запуск импорта
tests/           Автоматические проверки
docs/            Документация API, базы и модели прогноза
data/            Локальная база, кэш и отчёт импорта
```

## Тестирование

```bash
npm test
npm run test:browser
```

Серверные тесты используют отдельные базы в памяти. Для браузерных проверок нужны импортированные данные и установленный Chrome; при нестандартном расположении браузера задайте переменную `CHROME_PATH`. Скриншоты и отчёт сохраняются в `test-artifacts/` и не входят в репозиторий.
